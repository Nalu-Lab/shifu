- 对话之间可以直接问答了：`shifu ask <对话> <问题>` 把问题送进另一个对话并等它用 `shifu reply` 回答，答复作为命令结果直接回到提问的对话；等不到时，答复晚些自动送进提问的对话，带上原来问的是什么。`shifu read <对话>` 看另一个对话最近的输出，不用去屏幕上点开。每个 Claude、Codex 对话开工时都会被告知这几条命令，不再靠截图点击去找别的对话。
- 长消息不再卡在输入框里：组长或任务通知发来的多行或很长的消息，以前会被 Claude 折叠成「[Pasted text #4]」，Shifu 核对不上就不按回车，消息一直停在框里。现在长消息存成文件，输入框里只放一行带路径的短句，送进去后对方自己读全文。`shifu tell` 发给 Claude、Codex 时也走同一条排队路径：等输入框空了才送，不会盖掉你正在打的字。需要同时更新 App 和 `shifu` 命令行。
- Conversations can ask each other directly. `shifu ask <conversation> <question>` sends the question and waits for a `shifu reply`, which comes back as the command's result. If the asker stops waiting, the answer is queued into the asking conversation later, together with the question it answers. `shifu read <conversation>` shows another conversation's latest output without opening it on screen. Every Claude and Codex conversation is told these commands when it starts, so agents stop clicking through the window to reach each other.
- Long messages no longer get stuck in the input box. Claude folded a long or multi-line message from a lead or a task notice into "[Pasted text #4]"; Shifu could not match it and never pressed Enter. Long messages are now saved to a file, and the input box gets one short line with the path. `shifu tell` to Claude or Codex uses the same queue: it waits for an empty input box, so it never overwrites what you are typing. Needs both the app and the `shifu` CLI updated.

功能Features

为多个 Agent 并行工作而设计 Built for running agents in parallel

01

知道哪个 Agent 在等你Know which agent needs you

侧栏按项目和任务分组。支持状态反馈的 Agent 会标出在运行、在等批准还是在等你回复，需要你的集中在顶部「在等你」。 The sidebar groups conversations by project and task. For agents with status integration it marks who is running, waiting for approval or waiting for your reply, and the ones that need you collect at the top under “waiting for you”.

  • 按 ⌘J 跳到等待中的会话，批准请求优先⌘J jumps to a waiting conversation, approvals first
  • 状态来自 Agent 自己的 hook 或插件事件，不靠识别屏幕文字；各家支持到什么程度见兼容性States come from the agent's own hook or plugin events, not from reading the screen; compatibility shows what each agent reports
  • 右键「标为未读」「置顶」，⌘K 搜索对话Right-click to mark unread or pin; ⌘K searches conversations

02

真终端，不是聊天仿制品Real terminals, not a chat imitation

每个 Agent 跑在自己的终端里，界面、快捷键和确认框都是它本来的样子。同一个任务可以开好几个 Agent，拖动标签就能左右或上下分屏。 Each agent runs in its own terminal, with its own interface, shortcuts and prompts. Put several agents in one task and drag tabs to split them side by side or stacked.

03

关掉窗口，Agent 照样干活。Close the window. Your agents keep working.

Agent 跑在 Shifu 专用的 tmux 服务里，不在窗口里。退出、重开 Shifu，甚至 Shifu 崩溃，都不会让它们停下；回来时任务和分屏布局都在。 Agents run in Shifu's own tmux server, not in the window. Quitting and reopening Shifu, or even a Shifu crash, does not stop them, and tasks and split layouts come back.

重启 Mac 会结束 Agent 进程；之后点开对话，支持恢复的 Agent 会接回保存的会话。 Restarting the Mac does end the agent processes; when you open a conversation afterwards, agents that support it resume their saved session.

claude · codex · kimi … → tmux -L shifu-app → Shifu 窗口（可随时关掉）Shifu window (close any time)

Mac 睡眠和合盖时会怎样What happens when the Mac sleeps or the lid closes

Mac 睡着时，Agent 也会停。Shifu 运行时默认不让 Mac 因闲置而睡眠（屏幕仍可关闭）；合上盖子照样会睡，除非在窗口右下角的杯子菜单里授权一次「合盖时也保持运行」。这个模式在用电池且电量降到 10% 或 macOS 报告过热时会自动暂停。说明 When the Mac sleeps, the agents stop too. While Shifu runs it keeps the Mac from idle sleep by default (the display can still turn off). Closing the lid still puts it to sleep unless you authorize “keep running with the lid closed” once from the cup menu at the bottom right of the window; that mode pauses itself on battery at 10% or when macOS reports the Mac is running hot. 开源与隐私Open source and privacy

本机优先，代码公开Local first, source in the open

Shifu 以 MIT 许可证开源。下载包由 GitHub Actions 从公开源码构建，构建来源记录在包内的 BUILD-INFO.json。 Shifu is MIT-licensed. Download packages are built by GitHub Actions from the public source, with the build source recorded in BUILD-INFO.json inside the package.

Shifu 把工作区状态留在这台 Mac 上；你的 Agent 照旧连各自的 AI 服务商，适用这些服务商自己的政策。 Shifu keeps workspace state on this Mac; your agents still talk to their own AI providers under those providers' policies.

没有账号，没有遥测No account, no telemetry

Shifu 不提供托管账号，不收集遥测。状态、任务和布局保存在本机 ~/.shifu/app。 No hosted account and no telemetry. State, tasks and layouts stay on your Mac in ~/.shifu/app.

能独立配置的，就不动全局设置Isolated hooks where the agent allows it

Claude Code、Codex、CodeBuddy 的 hooks 只通过启动参数挂在 Shifu 启动的那个进程上，不改 ~/.claude/settings.json 或 ~/.codex/config.toml；opencode、Pi、Qwen Code、StepFun 的状态插件和配置放在 Shifu 自己的目录里。 Hooks for Claude Code, Codex and CodeBuddy are passed as launch arguments to the processes Shifu starts, so ~/.claude/settings.json and ~/.codex/config.toml stay unchanged; the status plugins and settings for opencode, Pi, Qwen Code and StepFun live in Shifu's own folder.

两个 Agent 要改全局配置Two agents need a global config change

Kimi Code 和 Antigravity 只从全局配置读 hooks：Shifu 在 ~/.kimi-code/config.toml 里加上自己的 hooks，在 ~/.gemini/config/hooks.json 里加一个 shifu-status 分组，你原有的内容都保留。文件已经存在时，第一次改动前会在同一目录备份成 config.toml.before-shifu / hooks.json.before-shifu。 Kimi Code and Antigravity read hooks only from a global config: Shifu adds its hooks to ~/.kimi-code/config.toml and a shifu-status group to ~/.gemini/config/hooks.json, keeping your own entries. If the file already exists, it is copied to config.toml.before-shifu / hooks.json.before-shifu in the same folder before the first change.

远程走你自己的线路Remote runs on your own route

手机入口只监听 127.0.0.1；Mac 之间用你自己配置的 HTTPS 中继，终端数据端到端加密。中继的网页也应来自你信任的服务器。 The phone gateway listens on 127.0.0.1; Mac-to-Mac uses your own HTTPS relay with end-to-end encrypted terminal data. Use a relay whose web client you trust.

FAQ

常见问题Questions

Shifu 收费吗？Does Shifu cost anything?
不收费。Shifu 以 MIT 许可证开源。你用的 Agent 本身怎么计费，仍按各家自己的订阅或额度。 No. Shifu is open source under the MIT license. The agents you run are still billed by their own subscriptions or quotas.
它会替代 Claude Code 或 Codex 吗？Does it replace Claude Code or Codex?
不会。Shifu 启动的就是这些 Agent 自己的命令行，你在终端里看到和操作的是它们原本的界面。Shifu 负责组织会话、显示状态和保持进程运行。 No. Shifu starts each agent's own CLI, and what you see in the terminal is that agent's own interface. Shifu organizes conversations, shows their state and keeps the processes running.
关掉窗口或退出 Shifu 后会怎样？What happens when I close or quit Shifu?
Agent 继续在 Shifu 专用的 tmux 服务里运行，Shifu 崩溃也一样。重新打开时任务和分屏布局恢复。重启 Mac 会结束 Agent 进程；之后点开对话，支持恢复的 Agent 会接回保存的会话（Gemini CLI 会重新开始）。标签上的 × 可以选择「收起，继续运行」或「结束」。 Agents keep running in Shifu's own tmux server, even if Shifu crashes. Reopen it and tasks and split layouts come back. Restarting the Mac ends the agent processes; when you open a conversation afterwards, agents that support it resume their saved session (Gemini CLI starts fresh). The × on a tab lets you hide it and keep it running, or end it.
支持 Intel Mac、Linux 或 Windows 吗？Intel Mac, Linux or Windows?
目前只有 Apple Silicon 的包，也只在 Apple Silicon 上用过。通知、拖放等用的是 macOS 接口。欢迎在 GitHub 上一起做跨平台。 Only an Apple Silicon package for now, and it has only been used there. Notifications and drag and drop use macOS interfaces. Cross-platform help is welcome on GitHub.
远程访问需要什么？What does remote access need?
连另一台 Mac：两边都装 Shifu，再准备一个两边都能访问的 HTTPS 中继（可用仓库里的 Docker 配置自建），然后配对。连手机：在电脑上装本机服务，再用 Tailscale 等私有网络从手机打开。都不提供公共托管服务。远程设置 · 手机连接 Another Mac: install Shifu on both, run an HTTPS relay both can reach (the repo has a Docker setup), then pair them. A phone: install the local service on the Mac and open it over a private network such as Tailscale. No hosted service is provided. Remote setup · Phone access (Chinese)
可以只用命令行吗？Can I use only the CLI?
可以。shifu 打开工作台，shifu new claude ~/proj 开一个 Agent，shifu ls 列出会话，shifu jump 跳到等待中的会话。命令行版用自己的 socket 和目录（~/.shifu）。 Yes. shifu opens the workbench, shifu new claude ~/proj starts an agent, shifu ls lists sessions and shifu jump opens a waiting one. The CLI uses its own socket and folder (~/.shifu).
